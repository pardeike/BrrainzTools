- Use the `brrainztools` skill and the `brrainztools` command on PATH as the preferred project tool for macOS desktop automation: screenshots, running-app discovery, desktop app/window/menu inspection, visible-window fallback capture, AX window listing/raising, in-window crops, menu capture, occluded-window capture, Accessibility-driven UX actions, app launch/quit/activation, semantic document opening, keyboard/mouse input, clipboard, waiting, and window management.
- Prefer `brrainztools --help` and `brrainztools <subcommand> --help` for exact command syntax instead of guessing or using raw `screencapture`, System Events AppleScript, or generic screenshot tooling first.
- Use BrrainzTools app discovery when the exact app name is unknown. If ScreenCaptureKit app/window capture fails or visible pixels are enough, use visible-window listing/capture before raw rectangle capture. If Screen Recording permission blocks app/window inspection but Accessibility works, use `brrainztools ax --app APP windows` and `brrainztools ax --app APP raise --window-index N` before AppleScript fallbacks.
- Use BrrainzTools menu-bar modes for menu-bar/status-item menus or popovers from accessory/background apps; use read-only `brrainztools menu --app APP tree` to inspect nested menu state/actions without opening menus or activating the app, and `brrainztools menu --app APP press-item TEXT` to choose child items inside status menus; use rectangle capture only for visible UI that is not exposed through app/window/visible-window/menu-bar commands.
- For local app development loops, prefer BrrainzTools primitives such as `brrainztools launch PATH|BUNDLE_ID --wait-window`, `brrainztools open-file DOCUMENT --app PATH|BUNDLE_ID --wait-window` for document handoffs, `brrainztools quit --app APP --wait` before an immediate relaunch, `brrainztools reveal PATH`, `brrainztools ax --app APP wait-for-element ...`, `set-value`, `type`, `key`, `click`, `drag`, `scroll`, `move`, `resize`, `close`, `minimize`, `brrainztools doctor`, and `brrainztools clipboard` before ad hoc sleeps or AppleScript.
- If System Events AppleScript seems necessary for screenshot/UX work, first treat that as a BrrainzTools capability gap: report the use case and suggest the BrrainzTools improvement before using the fallback.
- BrrainzTools is maintained by this project; if it has a bug or missing capability, report the concrete use case and suggest a tool improvement instead of silently accepting the limitation.
- BrrainzTools was formerly named RegionShot; treat `regionshot` references in older notes, logs, or scripts as stale and use `brrainztools` instead.
